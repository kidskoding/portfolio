Most people's first minute in Neovim is figuring out how to quit. After this post, yours will be different: fuzzy-open a file, change an argument without selecting it, rename a function across the project, review an AI diff, hit a breakpoint, commit, no mouse.

I bounced off Neovim in 2022 and spent years cycling through VS Code, [Zed](https://zed.dev), and whatever looked promising that month. What eventually stuck was a full editor first, not a clever keymap. This is that build. Keep VS Code installed; I still open it for full-grade IDE work. The point is a daily driver you can actually live in, not purity.

Reference copy of the same files: [nvimforge](https://github.com/kidskoding/nvimforge). Tools and platform installs: [appendix](#appendix-installing-everything). Already have a config? [Park it](#if-you-already-have-a-neovim-config).

## What Neovim is

[Neovim](https://neovim.io) is a modern fork of Vim: a **modal** text editor. You spend most of the time in <VimMode mode="normal" /> mode (keys move and change text) and drop into <VimMode mode="insert" /> only when you type. **VS Code is modeless:** you are always "typing" and the mouse plus chords (`Ctrl/Cmd+P`, multi-cursor, click-drag select) do the rest.

That sounds worse until you see what modal editing buys. In VS Code a small fix is often: reach for the mouse, select a word, type, click elsewhere, maybe open the Command Palette. In Neovim the same fix is a short sentence on the home row: `ciw` (change inside word), type the replacement, `Esc`. Operators (`c` change, `d` delete, `y` yank) compose with motions and text objects (`iw` inner word, `i(` inside parens, `ap` a paragraph). **You describe the edit instead of painting it.** After a week, that loop is faster than selecting with a mouse for the boring 80% of edits: rename a local, flip a condition, delete a function, jump to the next call site.

Neovim also stays out of your way as an app. It starts in tens of milliseconds, uses little RAM, is the same binary over SSH in terminal multiplexers like [tmux](https://github.com/tmux/tmux) or [Zellij](https://zellij.dev), and its whole UI is text you can script and theme. VS Code is a full Electron IDE: richer out of the box for giant refactor UIs and designer workflows, heavier to open, and its "remote" story is a different product surface. Neither wins every day. **Neovim wins the ordinary edit / navigate / commit day once the keys land.**

## The learning curve people fear

Many people are hesitant to switch because they expect setup to take weeks and think they have to memorize a long list of keys first. Both worries are fair if you assemble Neovim from scratch and drill `:Tutor` before you edit anything. **That is the wrong onboarding.**

**You do not memorize this post.** Space is the *leader* key (`<Leader>`). Press Space alone and [which-key](https://github.com/folke/which-key.nvim) lists what comes next, the way the Command Palette lists commands. Learn `ciw`, `gd`, and `<Leader>ff` when a real edit needs them; ignore the rest until friction shows up. The mouse still works for scrolling and clicking if you need a safety net.

**You do not configure inside Neovim on day one either.** This build is a handful of short **Lua** files. You edit them in VS Code, restart `nvim`, and only later live in the keys. **Replace day-to-day VS Code with a complete Neovim first, then learn each key when work demands it.**

## Why bother, when VS Code already has Claude Code and Copilot?

Fair question. Most people open VS Code today for the AI side panel as much as for the editor: chat with the project, get a diff, Accept or Reject. You are not giving that up. [Claude Code](https://docs.anthropic.com/en/docs/claude-code) is the same CLI Anthropic ships for VS Code; [claudecode.nvim](https://github.com/coder/claudecode.nvim) is the Neovim plugin that docks it beside your buffer the way the official VS Code extension does. Same agent, same review loop.

**You switch for the editor underneath:** instant start, SSH-native, config in Git as plain text, and that compose-the-edit pass once the keys land.

Costs are real: a slower first week, you own the config, big Java/Kotlin refactors and designers stay in an IDE. Keep VS Code or Cursor when they win a day. The rest of this post is how to make Neovim win the ordinary ones.

## Plugins are extensions

Neovim calls them **plugins**. Mentally map them to VS Code **extensions**: same job (add a theme, a file tree, a side panel), different packaging. In VS Code you install from the Marketplace (`publisher.name`) and tweak Settings. In Neovim each plugin is usually a GitHub repo written as `owner/repo` (example: `ellisonleao/gruvbox.nvim`), and you put options in a small **Lua** file next to that name. You will meet the plugin manager (Lazy) on first launch in the next section, and a second installer (Mason) only after you turn on language packs.

In VS Code, your user folder is `~/.config/Code/User/` on macOS/Linux (Windows: `%APPDATA%\Code\User\`). The two files you touch most are `settings.json` (behavior) and, if you pin a workspace kit, `extensions.json`:

```json
// ~/.config/Code/User/settings.json (trimmed)
{
  "workbench.colorTheme": "Gruvbox Dark Medium",
  "editor.fontFamily": "JetBrains Mono",
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "charliermarsh.ruff",
  "[python]": {
    "editor.defaultFormatter": "charliermarsh.ruff"
  }
}
```

```json
// .vscode/extensions.json in a project (optional)
{
  "recommendations": [
    "jdinhlife.gruvbox",
    "anthropic.claude-code",
    "charliermarsh.ruff",
    "ms-python.python"
  ]
}
```

Neovim does the same job with a folder of **Lua** files instead of one big **JSON** blob. **The whole tree is text you can put in Git.**

[AstroNvim](https://astronvim.com) is a ready-made Neovim that already includes most of what a VS Code user expects (Explorer, fuzzy find, debugger, terminal, Git signs). You add a theme, language tools, the Claude Code side panel, and session restore. **Configure in VS Code until the tour: no Neovim keys required for setup.**

The table below is only a map of familiar VS Code pieces to where they live in this build. Each row gets a real introduction when you configure it in the next section.

| VS Code | Neovim (this build) |
|---|---|
| Marketplace + Extensions view | lines in `lua/community.lua` + small files under `lua/plugins/` + `:Lazy` |
| Extension Pack / recommended extensions | one AstroCommunity `import` line |
| `settings.json` | `lua/plugins/astrocore.lua` (`opt`, keymaps) |
| Color Theme picker | `lua/plugins/astroui.lua` + a theme file like `gruvbox.lua` |
| Extension-specific settings | `opts = { ... }` in that plugin's **Lua** file |
| Language servers / formatters (often bundled in an extension) | `:Mason` installs the binaries those plugins call |
| Status bar / tabs | `lualine` + `bufferline` (two small files) |
| Explorer / `Ctrl/Cmd+P` | Neo-tree / `<Leader>ff` (built in) |
| Pylance, format-on-save, etc. | One AstroCommunity line per tool |
| Run and Debug / Terminal / Source Control | Built in (`F5`/`F9`, `F7`, `lazygit`) |
| Claude Code side panel | Same Claude Code, via `claudecode.nvim` |
| Reopen last files | One line |

## Configuring Neovim

Time to build it. You clone a ready-made config, launch Neovim once so it can finish downloading, then edit that folder in VS Code the same way you edit User settings. Pattern for everything below: **file → few lines → restart `nvim`.**

```sh
git clone --depth 1 https://github.com/AstroNvim/template ~/.config/nvim
rm -rf ~/.config/nvim/.git
nvim   # wait for the download UI to finish
```

The first launch runs [lazy.nvim](https://github.com/folke/lazy.nvim) (**Lazy**): AstroNvim's plugin manager. It clones the built-in plugins from GitHub onto your machine, the way the Extensions view installs Marketplace packages. Wait until that finishes; do not close the terminal mid-download.

When it settles, you are not in a file yet. You are on the **dashboard**: AstroNvim's start page (Get Started / welcome screen energy). Big logo, a short menu of actions, each with a single-key shortcut. It is a launcher, not a document. (When you do open a file, Neovim calls that open document a **buffer**, same idea as the file in a VS Code tab.)

To leave Neovim, you use a **colon command**: press `:`, type a command name, press Enter. That is Neovim's "run this by name" box (cousin of the Command Palette, but typed after a colon). Quit everything with `:qa` (quit all), then Enter.

From here on, edit the config in VS Code, not inside Neovim yet:

```sh
code ~/.config/nvim
```

Template example files start with a **guard line**, `if true then return {} end`. That means "ignore the rest of this file." Delete that line or your changes never load.

Work through these in order: theme → dashboard → community imports → check Lazy, then Mason → status bar and tabs → command line → Claude panel → which-key polish.

### Theme

Same job as `"workbench.colorTheme"` in `settings.json`. You are adding a **theme plugin**: [gruvbox.nvim](https://github.com/ellisonleao/gruvbox.nvim). Create `lua/plugins/gruvbox.lua`. The first string (`"ellisonleao/gruvbox.nvim"`) is the plugin id Lazy will clone from GitHub (`owner/repo`), the way the Marketplace installs a theme extension. `opts` is the settings table for that plugin. `priority = 1000` loads it before other plugins so colors apply cleanly. The `SignColumn` / `FoldColumn` overrides clear the gray band AstroNvim leaves in those gutters under `gruvbox`. (which-key colors go in this same file later.)

```lua
-- lua/plugins/gruvbox.lua
return {
  "ellisonleao/gruvbox.nvim",
  priority = 1000,
  opts = {
    overrides = {
      SignColumn = { link = "Normal" },
      FoldColumn = { link = "Normal" },
    },
  },
}
```

Installing the plugin is not enough; you still have to select it, the way you pick a Color Theme after installing one. **astroui** (`AstroNvim/astroui`) is AstroNvim's UI settings plugin (colorscheme, icons). Open `lua/plugins/astroui.lua`, delete the guard line at the top, and set `colorscheme` to `"gruvbox"`:

```lua
-- lua/plugins/astroui.lua (template, trimmed)
return {
  "AstroNvim/astroui",
  opts = {
    colorscheme = "gruvbox",
  },
}
```

Save both, run `nvim`, and the same dashboard picks up `gruvbox` (same rows, new colors). That is the whole pattern for the rest of this section: create or open a file, write the few lines you need, restart.

### Dashboard

**The gruvbox dashboard you see above** (logo plus the New File / Find File / Recents / Find Word / Bookmarks / Last Session menu) is drawn by a plugin AstroNvim already installed for you: [Snacks.nvim](https://github.com/folke/snacks.nvim) (`folke/snacks.nvim`). Snacks is a kitchen-sink plugin: start page, pickers, terminal helpers, notifications. **You are not installing Snacks. You are editing its settings,** the same way you tweak an already-installed VS Code extension.

Create `lua/plugins/snacks.lua` that names `"folke/snacks.nvim"` again so Lazy merges your `opts` into the existing install. The only table you change is `dashboard.preset.keys`: that is the list of splash rows. Each row is `{ key, action, icon, desc }`. `key` is the letter you press on the splash, `action` is the command or Space-leader map it runs, `desc` is the label next to it.

Stock still shows Find Word and Bookmarks, and it has no Quit. **Trim it to five rows you will actually use:** New File, Find File, Recents, Last Session, and Quit. Drop Find Word (project search stays on Space then `fw` once you have a file open; Space is the leader key from earlier) and Bookmarks. `q` runs `:qa`, the same quit you already used. The `opts` function receives AstroNvim's merged Snacks settings; you replace `keys`, then `nil` out any leftover stock rows Lazy may have concatenated onto the list:

```lua
-- lua/plugins/snacks.lua
return {
  "folke/snacks.nvim",
  opts = function(_, opts)
    local get_icon = require("astroui").get_icon

    opts.dashboard = opts.dashboard or {}
    opts.dashboard.preset = opts.dashboard.preset or {}

    -- Full list, then clear leftover stock rows Lazy may have merged in.
    opts.dashboard.preset.keys = {
      { key = "n", action = "<Leader>n", icon = get_icon("FileNew", 0, true), desc = "New File  " },
      { key = "f", action = "<Leader>ff", icon = get_icon("Search", 0, true), desc = "Find File  " },
      { key = "o", action = "<Leader>fo", icon = get_icon("DefaultFile", 0, true), desc = "Recents  " },

      { key = "s", action = "<Leader>Sl", icon = get_icon("Refresh", 0, true), desc = "Last Session  " },

      { key = "q", action = ":qa", icon = get_icon("BufferClose", 0, true), desc = "Quit  " },
    }

    for i = #opts.dashboard.preset.keys + 1, 12 do
      opts.dashboard.preset.keys[i] = nil
    end
  end,
}
```

`get_icon(...)` pulls AstroNvim's Nerd Font glyphs so the row icons match the rest of the UI. Restart once more. The dashboard should now look like this (Find Word and Bookmarks gone, Quit on `q`):

### community.lua

You already told Lazy about one plugin by hand (`gruvbox`). [AstroCommunity](https://github.com/AstroNvim/astrocommunity) is the shortcut for the rest: a catalog of **packs**, each a ready-made bundle (plugins + defaults + keys). One `{ import = "..." }` line is closer to installing a VS Code Extension Pack than writing every `owner/repo` yourself.

Open `lua/community.lua`, delete the guard line, and paste this whole file (it matches [nvimforge](https://github.com/kidskoding/nvimforge)). Read the comments in the file as you paste; the next paragraphs walk the same lines in order.

```lua
-- lua/community.lua
-- AstroCommunity: ready-made plugin packs, turned on with one `import` line each
-- browse everything available here: https://github.com/AstroNvim/astrocommunity

---@type LazySpec
return {
  "AstroNvim/astrocommunity",

  { import = "astrocommunity.pack.lua" }, -- helps when editing these config files

  { import = "astrocommunity.bars-and-lines.lualine-nvim" }, -- the status bar
  { import = "astrocommunity.bars-and-lines.bufferline-nvim" }, -- the tabs

  -- languages (uncomment the languages you use!)
  -- check out all available language extension packs here: https://github.com/AstroNvim/astrocommunity/tree/main/lua/astrocommunity/pack
  { import = "astrocommunity.pack.python.base" }, -- Python syntax, the debugger, and a virtualenv picker
  { import = "astrocommunity.pack.python.ty" }, -- ty: type checking, go-to-definition, and hover docs
  { import = "astrocommunity.pack.python.ruff" }, -- Ruff: linting and formatting for Python
  -- { import = "astrocommunity.pack.typescript" },
  -- { import = "astrocommunity.pack.rust" },

  { import = "astrocommunity.ai.claudecode-nvim" },

  { import = "astrocommunity.recipes.auto-session-restore" },
}
```

Top to bottom:

1. `pack.lua` turns on smart editing for the **Lua** files in this config folder (completion and diagnostics while you edit setup).
2. `lualine` and `bufferline` are the status bar (bottom) and tabs (top). You will tweak their colors in the next subsection.
3. The **Python** block is three packs. `python.base` is syntax, debugger wiring, and a virtualenv picker. `python.ty` pulls in [ty](https://docs.astral.sh/ty/) for types, jump-to-definition, and hover (Pylance's job in VS Code). `python.ruff` pulls in [Ruff](https://docs.astral.sh/ruff/) for lint squiggles and format on save. Do not also enable a plain `pack.python` import, or two toolchains fight.
4. The commented **TypeScript** / **Rust** lines stay commented until you use those languages.
5. The Claude Code line is the side-panel **plugin**. The `claude` CLI is separate; install that from the appendix when you reach the panel step.
6. The last line restores the files you had open the next time you run `nvim` in a folder with no file argument, like VS Code reopening a workspace.

AstroNvim already ships Neo-tree (Explorer), the fuzzy finder (`Ctrl/Cmd+P`), the debugger keys (`F5` / `F9` / `F10`), the terminal (`F7`), and Git signs. `lazygit` and `claude` are still OS installs from the appendix, not Lazy plugins.

Save `community.lua`. Those `import` lines only *wire* features into Neovim. Lazy still has to download the new plugins, and the Python packs still need programs on disk (`ty`, `ruff`, …) before jump-to-definition or format-on-save can work. Next, you restart, confirm Lazy got the plugins, then let Mason install those programs.

### Install the language tools with Mason

In VS Code, installing the Python extension often fetches jump-to-definition and formatting behind the scenes. Here the `community.lua` lines chose *which* tools to use; a second installer, [mason.nvim](https://github.com/williamboman/mason.nvim) (**Mason**), puts the actual programs on your machine.

Example you already pasted: `{ import = "astrocommunity.pack.python.ruff" }` means "wire Neovim to Ruff." It does not download Ruff. Mason downloads the `ruff` program. Until that finishes, format-on-save has nothing to run. Same idea for `ty` (types / jump-to-definition), `lua_ls` (smart editing for your **Lua** config), and `debugpy` (what breakpoints / `F5` talk to).

Still in <VimMode mode="normal" />, type `:Mason`, press Enter:

| You want… | Open |
|---|---|
| Theme, status bar, tabs, Claude panel, community packs | `:Lazy` (plugins you already know) |
| `ty`, `ruff`, `lua_ls`, `debugpy` | `:Mason` (programs those packs call) |
| `lazygit` or the `claude` CLI | your OS package manager / their docs |

Community lines only turn features on with defaults. Everything below follows one pattern you already used for Snacks and gruvbox: create a small file under `lua/plugins/`, name the same `owner/repo` again, and put settings in `opts`. Lazy merges that table into the install, like changing an extension's settings in VS Code after it is already installed.

### Status bar and tabs

In `community.lua` you imported two UI packs: **lualine** (bottom status bar: mode, branch, file info) and **bufferline** (top tabs for open files). Both are already installed; these files only change how they look.

First, lualine (`nvim-lualine/lualine.nvim`). Create `lua/plugins/lualine.lua`. The snippet starts from lualine's built-in `gruvbox` theme, paints <VimMode mode="normal" /> yellow, and paints <VimMode mode="terminal" /> purple so terminal-style panels (the built-in terminal on `F7`, and the Claude panel you wire next) do not stay yellow. `globalstatus = true` uses one status bar for the whole screen, like VS Code.

```lua
-- lua/plugins/lualine.lua
return {
  "nvim-lualine/lualine.nvim",
  opts = function()
    local theme = require("lualine.themes.gruvbox_dark")

    theme.normal.a.bg = "#fabd2f"

    theme.terminal = vim.deepcopy(theme.insert)
    theme.terminal.a.bg = "#d3869b"

    for _, mode in pairs(theme) do
      mode.c = theme.normal.c
    end

    return { options = { theme = theme, globalstatus = true } }
  end,
}
```

Next, bufferline (`akinsho/bufferline.nvim`), the tab bar. Create `lua/plugins/bufferline.lua`. This uses a minimal preset (no bold/italic chrome), less empty padding per tab, and a fill color that matches the editor so the dashboard is not a black strip across the top. The `offsets` entries leave a gap for Neo-tree (AstroNvim's file explorer, already shipped) and for Snacks layout panels so tabs do not draw over those side columns.

```lua
-- lua/plugins/bufferline.lua
return {
  "akinsho/bufferline.nvim",
  opts = function(_, opts)
    local bufferline = require "bufferline"
    local normal_bg = vim.api.nvim_get_hl(0, { name = "Normal", link = false }).bg or "#282828"

    opts.options = vim.tbl_deep_extend("force", opts.options or {}, {
      style_preset = {
        bufferline.style_preset.minimal,
        bufferline.style_preset.no_italic,
      },
      tab_size = 0,
      separator_style = { "", "" },
      offsets = {
        {
          filetype = "neo-tree",
          text = "Neo-tree",
          highlight = "Directory",
          text_align = "left",
        },
        {
          filetype = "snacks_layout_box",
          separator = true,
          highlight = "Normal",
        },
      },
    })

    opts.highlights = vim.tbl_deep_extend("force", opts.highlights or {}, {
      fill = { bg = normal_bg },
      background = { bg = normal_bg },
      indicator_selected = { fg = "#d79921" },
      offset_separator = { bg = normal_bg },
    })

    return opts
  end,
}
```

### Command line

**astrocore** (`AstroNvim/astrocore`) is AstroNvim's core settings plugin: options, keymaps, and autocmds in one place. Treat `lua/plugins/astrocore.lua` like `settings.json`. Open it, delete the guard line, and set `cmdheight = 1`.

AstroNvim hides the command line by default, so when you type after `:` the text sits on top of the status bar and lualine never shows <VimMode mode="command" /> mode. `cmdheight = 1` gives `:` its own row underneath, like the Command Palette not covering the status bar.

```lua
-- lua/plugins/astrocore.lua (template, trimmed; delete the guard line)
return {
  "AstroNvim/astrocore",
  opts = {
    options = {
      opt = {
        cmdheight = 1,
      },
    },
  },
}
```

### Claude Code panel

Back in `community.lua`, `{ import = "astrocommunity.ai.claudecode-nvim" }` installed **claudecode.nvim** (`coder/claudecode.nvim`): the plugin that docks Anthropic's Claude Code CLI in a side panel, the way the official VS Code extension does. You still need the `claude` CLI on your PATH (appendix); the plugin only hosts it inside Neovim.

Out of the box the panel can look like a duplicate buffer (extra title bars under the real tabs). Two small merges fix that. The first file tweaks the Claude plugin's terminal window. The second touches **heirline** (`rebelot/heirline.nvim`), AstroNvim's default winbar plugin (the per-window title strip above a buffer). Clearing `opts.winbar` removes that strip so Claude's panel does not stack a second chrome under bufferline.

```lua
-- lua/plugins/claudecode.lua
return {
  "coder/claudecode.nvim",
  opts = {
    terminal = {
      snacks_win_opts = {
        wo = { winbar = "" },
      },
    },
  },
}
```

```lua
-- lua/plugins/heirline.lua
return {
  "rebelot/heirline.nvim",
  opts = function(_, opts)
    opts.winbar = nil
    return opts
  end,
}
```

### which-key

You met [which-key](https://github.com/folke/which-key.nvim) in the learning-curve section: press Space (the leader) and it lists what comes next, Command Palette cheat-sheet energy. AstroNvim already ships that plugin; you are not adding a new `import` line.

Under `gruvbox`, the popup can look empty until which-key's highlight groups link into the theme. Open `lua/plugins/gruvbox.lua` again (the theme plugin you created first) and add the which-key block under `overrides` so the file looks like this:

```lua
-- lua/plugins/gruvbox.lua
return {
  "ellisonleao/gruvbox.nvim",
  priority = 1000,
  opts = {
```

## Appendix: installing everything

### What you need

| Tool | Why | Check |
|---|---|---|
| Neovim 0.11+ | Editor (AstroNvim v6 min; written against 0.12) | `nvim --version` |
| Git | Config and plugins | `git --version` |
| Node.js | Most language servers | `node --version` |
| C compiler | Tree-sitter parsers | `gcc --version` or `clang --version` |
| tree-sitter CLI | Parsers | `tree-sitter --version` |
| ripgrep | Project search | `rg --version` |
| fd | File search | `fd --version` |
| Nerd Font | Icons | [Fonts](#fonts-and-icons) |
| lazygit | Git UI | `lazygit --version` |
| Claude Code | Agent | `claude --version` |
| Python 3 | Examples | `python3 --version` |
| Neovide | Optional GUI | `neovide --version` |

Linux clipboard: `wl-clipboard` or `xclip`. nvimforge's flake also pulls ripgrep, fd, tree-sitter, lazygit, Node, and a C compiler.

### Installing the tools

From Neovim's [install guide](https://github.com/neovim/neovim/blob/master/INSTALL.md); Claude Code from [its docs](https://docs.anthropic.com/en/docs/claude-code):

```sh
# macOS
xcode-select --install
brew install neovim git node ripgrep fd lazygit
brew install --cask font-jetbrains-mono-nerd-font

# Windows (PowerShell)
winget install Neovim.Neovim Git.Git OpenJS.NodeJS.LTS \
  BurntSushi.ripgrep.MSVC sharkdp.fd JesseDuffield.lazygit

# Arch
sudo pacman -S neovim git nodejs npm base-devel \
  ripgrep fd tree-sitter-cli lazygit

# Debian / Ubuntu (Neovim from tarball below)
sudo apt install git nodejs npm build-essential ripgrep fd-find unzip

# Other Linux x86_64
curl -LO \
  https://github.com/neovim/neovim/releases/latest/download/nvim-linux-x86_64.tar.gz
sudo tar -C /opt -xzf nvim-linux-x86_64.tar.gz
export PATH="$PATH:/opt/nvim-linux-x86_64/bin"
```

If `nvim --version` is older than 0.11, use the tarball and put the `export` in your shell rc. Debian/Ubuntu: `fd` is `fdfind`. Windows needs a C compiler (e.g. VS Build Tools). Missing tree-sitter CLI: drop the guard in template `lua/plugins/mason.lua`.

### Fonts and icons

[Nerd Font](https://www.nerdfonts.com/font-downloads) in the terminal, or `icons_enabled = false` in `lua/lazy_setup.lua`.

### Neovide

[Install](https://neovide.dev/installation.html), then `neovide` uses this config. GUI font example in `lua/polish.lua`: `vim.o.guifont = "JetBrainsMono Nerd Font:h14"`. Nix: `nix run .#neovide` from nvimforge.

### Windows template path

Same order as above: clone, launch once for the dashboard, quit, then edit in VS Code.

```powershell
git clone --depth 1 https://github.com/AstroNvim/template $env:LOCALAPPDATA\nvim
Remove-Item $env:LOCALAPPDATA\nvim\.git -Recurse -Force
nvim   # wait for plugins, then :qa

```

### When it doesn't work

- Boxes for icons → Nerd Font or `icons_enabled = false`
- No highlights → C compiler / tree-sitter CLI on `PATH`
- LSP dead → `:Mason`, language toolchain installed
- No `<Leader>fw` → install ripgrep
- Config ignored → still have `if true then return {} end`
- Stale red errors → `:w` / `:LspRestart`
- No Claude panel → `claude` works in a shell
- Nuclear → `:checkhealth`, or `nvim --clean`

### If you already have a Neovim config

```sh
mv ~/.config/nvim ~/.config/nvim.bak
mv ~/.local/share/nvim ~/.local/share/nvim.bak
mv ~/.local/state/nvim ~/.local/state/nvim.bak
mv ~/.cache/nvim ~/.cache/nvim.bak
```

### Undoing it

```sh
rm -rf ~/.config/nvim \
  ~/.local/share/nvim \
  ~/.local/state/nvim \
  ~/.cache/nvim
mv ~/.config/nvim.bak ~/.config/nvim
mv ~/.local/share/nvim.bak ~/.local/share/nvim
mv ~/.local/state/nvim.bak ~/.local/state/nvim
mv ~/.cache/nvim.bak ~/.cache/nvim
```

### Nix

`nix shell nixpkgs#neovim`; on NixOS add packages to `environment.systemPackages`. Mason + NixOS often needs `programs.nix-ld` or nixpkgs tools instead. nvimforge's `flake.nix` runs this config beside an existing Neovim install.
