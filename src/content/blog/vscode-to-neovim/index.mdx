Most people's first minute in Neovim is figuring out how to quit. After this post yours is different: fuzzy-open a file, change an argument without selecting it, rename a function across the project, review an AI diff, hit a breakpoint, commit, no mouse.

The usual reasons not to switch are that setup takes weeks and that you must memorize a wiki of keys. Both are true if you assemble Neovim from scratch and drill `:Tutor` before you edit anything. You don't have to. **You can replace day-to-day VS Code with a complete Neovim in a handful of short files, then learn each key when a real edit needs it.**

I bounced off Neovim in 2022 and spent years cycling through VS Code, [Zed](https://zed.dev), and whatever looked promising that month. What eventually stuck was a full editor first, not a clever keymap. This is that build. Keep VS Code installed; I still open it for full-grade IDE work. The point is a daily driver you can actually live in, not purity.

Reference copy of the same files: [nvimforge](https://github.com/kidskoding/nvimforge). Tools and platform installs: [appendix](#appendix-installing-everything). Already have a config? [Park it](#if-you-already-have-a-neovim-config).

---

## What you get

[AstroNvim](https://astronvim.com) is a ready-made Neovim that already includes most of what a VS Code user expects. You add a theme, language tools, the Claude Code side panel, and session restore. Configure in VS Code until the tour: no Neovim keys required for setup.

| VS Code | Here |
|---|---|
| Color Theme | You add gruvbox |
| Status bar / tabs | lualine + bufferline (two small files) |
| Explorer / `Ctrl/Cmd+P` | Neo-tree / `<Leader>ff` (built in) |
| Pylance, format-on-save, etc. | One AstroCommunity line per tool |
| Run and Debug / Terminal / Source Control | Built in (`F5`/`F9`, `F7`, lazygit) |
| Claude Code side panel (the VS Code extension) | Same Claude Code, via claudecode.nvim |
| Reopen last files | One line |

Space is the *leader* key (`<Leader>`). Press Space alone and [which-key](https://github.com/folke/which-key.nvim) lists what comes next, so you do not memorize this post.

---

## Why bother, when VS Code already has Claude Code and Copilot?

Fair question. Most people open VS Code today for the AI side panel as much as for the editor: chat with the project, get a diff, Accept or Reject. You are not giving that up. [Claude Code](https://docs.anthropic.com/en/docs/claude-code) is the same CLI Anthropic ships for VS Code; [claudecode.nvim](https://github.com/coder/claudecode.nvim) is the Neovim plug that docks it beside your buffer the way the official VS Code extension does. Same agent, same review loop.

You switch for the editor underneath: Neovim starts instantly, runs the same over SSH in [tmux](https://github.com/tmux/tmux) or [Zellij](https://zellij.dev), lives in Git as plain text, and once the keys land, makes the read / navigate / small-fix pass faster than painting selections with a mouse.

Costs are real: a slower first week, you own the config, big Java/Kotlin refactors and designers stay in an IDE. Keep VS Code or Cursor when they win a day. The rest of this post is how to make Neovim win the ordinary ones.

## Config

In VS Code you already configure the editor as JSON. Install an extension from the marketplace, then tweak it in Settings (UI) or by editing the files under your user folder: on macOS/Linux that is `~/.config/Code/User/` (Windows: `%APPDATA%\Code\User\`). The two you touch most are `settings.json` (behavior) and, if you pin a workspace kit, something like `extensions.json` recommending what to install:

```json
// ~/.config/Code/User/settings.json (trimmed)
{
  "workbench.colorTheme": "Gruvbox Dark Medium",
  "editor.fontFamily": "JetBrains Mono",
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "charliermarsh.ruff",
  "[python]": {
    "editor.defaultFormatter": "charliermarsh.ruff"
  }
}
```

```json
// .vscode/extensions.json in a project (optional)
{
  "recommendations": [
    "jdinhlife.gruvbox",
    "anthropic.claude-code",
    "charliermarsh.ruff",
    "ms-python.python"
  ]
}
```

Neovim does the same job with a folder of Lua files instead of one big JSON blob. Plugins are listed by GitHub name (Lazy.nvim downloads them the way the marketplace installs extensions), options live next to the plugin, and the whole tree is just text you can put in Git. AstroNvim's layout maps roughly like this:

| VS Code | Neovim (this build) |
|---|---|
| Marketplace + Extensions view | lines in `lua/community.lua` (and small files under `lua/plugins/`) |
| `settings.json` | `lua/plugins/astrocore.lua` (`opt`, keymaps) |
| Color Theme picker | `lua/plugins/astroui.lua` + a theme file like `gruvbox.lua` |
| Extension-specific settings | `opts = { ... }` in that plugin's Lua file |

Install the template and open Neovim once so Lazy can pull plugins (you will open `:Lazy` and `:Mason` after the community imports below). You land on the stock dashboard:

```sh
git clone --depth 1 https://github.com/AstroNvim/template ~/.config/nvim
rm -rf ~/.config/nvim/.git
nvim   # wait for plugins to finish
```

Template example files start with `if true then return {} end`: delete that line or nothing loads. Pattern for everything below: **file → few lines → restart `nvim`.**

Work through these in order: theme → dashboard → community imports → Lazy/Mason → status bar and tabs → command line → Claude panel → which-key polish.

### Theme

Same job as `"workbench.colorTheme"` in `settings.json`. Create `lua/plugins/gruvbox.lua`. The first string is the plugin's GitHub name (Lazy.nvim installs it like the marketplace). `priority = 1000` loads the theme before other plugins so colors apply cleanly. The `SignColumn` / `FoldColumn` overrides clear the gray band AstroNvim leaves in those gutters under gruvbox. (which-key colors come later.)

```lua
-- lua/plugins/gruvbox.lua
return {
  "ellisonleao/gruvbox.nvim",
  priority = 1000,
  opts = {
    overrides = {
      SignColumn = { link = "Normal" },
      FoldColumn = { link = "Normal" },
    },
  },
}
```

Then select it, the way you pick a Color Theme after installing one. Open `lua/plugins/astroui.lua`, delete the guard line at the top, and set `colorscheme` to `"gruvbox"`:

```lua
-- lua/plugins/astroui.lua (template, trimmed)
return {
  "AstroNvim/astroui",
  opts = {
    colorscheme = "gruvbox",
  },
}
```

Save both, run `nvim`, and the dashboard picks up gruvbox. That is the whole pattern for the rest of this section: create or open a file, write the few lines you need, restart.

### Dashboard

Stock still lists Find Word and Bookmarks, and it skips Quit. Keep five splash rows: New File, Find File, Recents, Last Session, and Quit. Drop Find Word (you still have `<Leader>fw` for project search) and Bookmarks. `q` is the same `:qa` you already used. Create `lua/plugins/snacks.lua`:

```lua
-- lua/plugins/snacks.lua
return {
  "folke/snacks.nvim",
  opts = function(_, opts)
    local get_icon = require("astroui").get_icon

    opts.dashboard = opts.dashboard or {}
    opts.dashboard.preset = opts.dashboard.preset or {}

    -- Full list, then clear leftover stock rows Lazy may have merged in.
    opts.dashboard.preset.keys = {
      { key = "n", action = "<Leader>n", icon = get_icon("FileNew", 0, true), desc = "New File  " },
      { key = "f", action = "<Leader>ff", icon = get_icon("Search", 0, true), desc = "Find File  " },
      { key = "o", action = "<Leader>fo", icon = get_icon("DefaultFile", 0, true), desc = "Recents  " },

      { key = "s", action = "<Leader>Sl", icon = get_icon("Refresh", 0, true), desc = "Last Session  " },

      { key = "q", action = ":qa", icon = get_icon("BufferClose", 0, true), desc = "Quit  " },
    }

    for i = #opts.dashboard.preset.keys + 1, 12 do
      opts.dashboard.preset.keys[i] = nil
    end
  end,
}
```

### community.lua

[AstroCommunity](https://github.com/AstroNvim/astrocommunity) is the closest thing to the Extensions marketplace: one `import` line turns on a ready-made feature (the plugin, its dependencies, and its keys). Open `lua/community.lua`, delete the guard line, and paste this whole file (it matches [nvimforge](https://github.com/kidskoding/nvimforge)).

The `pack.lua` line was already in the template; it helps when you edit these config files. lualine and bufferline are the status bar and tabs. The Python lines use [ty](https://docs.astral.sh/ty/) (types, go-to-definition, hover: Pylance's job) and [Ruff](https://docs.astral.sh/ruff/) (lint + format on save). Do not also enable the plain `pack.python` import, or you get two competing toolchains. Uncomment TypeScript, Rust, and so on only for languages you actually have installed. The Claude Code line is the side panel. The last line restores open files when you `nvim` in a folder with nothing after it, like VS Code reopening a workspace.

```lua
-- lua/community.lua
-- AstroCommunity: ready-made plugin setups, turned on with one `import` line each
-- browse everything available here: https://github.com/AstroNvim/astrocommunity

---@type LazySpec
return {
  "AstroNvim/astrocommunity",

  { import = "astrocommunity.pack.lua" }, -- helps when editing these config files

  { import = "astrocommunity.bars-and-lines.lualine-nvim" }, -- the status bar
  { import = "astrocommunity.bars-and-lines.bufferline-nvim" }, -- the tabs

  -- languages (uncomment the languages you use!)
  -- check out all available language extension packs here: https://github.com/AstroNvim/astrocommunity/tree/main/lua/astrocommunity/pack
  { import = "astrocommunity.pack.python.base" }, -- Python syntax, the debugger, and a virtualenv picker
  { import = "astrocommunity.pack.python.ty" }, -- ty: type checking, go-to-definition, and hover docs
  { import = "astrocommunity.pack.python.ruff" }, -- Ruff: linting and formatting
  -- { import = "astrocommunity.pack.typescript" },
  -- { import = "astrocommunity.pack.rust" },

  { import = "astrocommunity.ai.claudecode-nvim" },

  { import = "astrocommunity.recipes.auto-session-restore" },
}
```

AstroNvim already ships Neo-tree (Explorer), the fuzzy finder (`Ctrl/Cmd+P`), the debugger (`F5` / `F9` / `F10`), the terminal (`F7`), and Git signs. You still need `lazygit` and the `claude` CLI from the appendix / their docs.

### Status bar and tabs

Create `lua/plugins/lualine.lua`. This starts from lualine's gruvbox theme, makes Normal mode yellow, gives Terminal mode purple (Claude Code, `F7`, lazygit: without this, Terminal stays yellow), keeps the middle of the bar stable across modes, and uses one status bar for the whole screen, like VS Code's.

```lua
-- lua/plugins/lualine.lua
return {
  "nvim-lualine/lualine.nvim",
  opts = function()
    local theme = require("lualine.themes.gruvbox_dark")

    theme.normal.a.bg = "#fabd2f"

    theme.terminal = vim.deepcopy(theme.insert)
    theme.terminal.a.bg = "#d3869b"

    for _, mode in pairs(theme) do
      mode.c = theme.normal.c
    end

    return { options = { theme = theme, globalstatus = true } }
  end,
}
```

Create `lua/plugins/bufferline.lua` for the tabs. Minimal preset (no bold/italic chrome), less empty padding per tab, and a fill color that matches the editor so the dashboard is not a black strip across the top.

```lua
-- lua/plugins/bufferline.lua
return {
  "akinsho/bufferline.nvim",
  opts = function(_, opts)
    local bufferline = require "bufferline"
    local normal_bg = vim.api.nvim_get_hl(0, { name = "Normal", link = false }).bg or "#282828"

    opts.options = vim.tbl_deep_extend("force", opts.options or {}, {
      style_preset = {
        bufferline.style_preset.minimal,
        bufferline.style_preset.no_italic,
      },
      tab_size = 0,
      separator_style = { "", "" },
      offsets = {
        {
          filetype = "neo-tree",
          text = "Neo-tree",
          highlight = "Directory",
          text_align = "left",
        },
        {
          filetype = "snacks_layout_box",
          separator = true,
          highlight = "Normal",
        },
      },
    })

    opts.highlights = vim.tbl_deep_extend("force", opts.highlights or {}, {
      fill = { bg = normal_bg },
      background = { bg = normal_bg },
      indicator_selected = { fg = "#d79921" },
      offset_separator = { bg = normal_bg },
    })

    return opts
  end,
}
```

### Command line

Open `lua/plugins/astrocore.lua` (this is your `settings.json`), delete the guard line, and set `cmdheight = 1`. AstroNvim hides the command line by default, so typing after `:` sits on top of the status bar and lualine never shows Command mode. This gives `:` its own row underneath, like the Command Palette not covering the status bar.

```lua
-- lua/plugins/astrocore.lua (template, trimmed; delete the guard line)
return {
  "AstroNvim/astrocore",
  opts = {
    options = {
      opt = {
        cmdheight = 1,
      },
    },
  },
}
```

### which-key

AstroNvim already opens [which-key](https://github.com/folke/which-key.nvim) when you press Space. Under gruvbox the popup can look empty until its highlight groups link into the theme. Open `lua/plugins/gruvbox.lua` again and add the which-key block under `overrides` so the file looks like this:

```lua
-- lua/plugins/gruvbox.lua
return {
  "ellisonleao/gruvbox.nvim",
  priority = 1000,
  opts = {
    overrides = {
      SignColumn = { link = "Normal" },
      FoldColumn = { link = "Normal" },

      -- which key overrides
      WhichKey = { link = "Function" },
      WhichKeyNormal = { link = "NormalFloat" },
      WhichKeyBorder = { link = "FloatBorder" },
      WhichKeyDesc = { link = "Identifier" },
      WhichKeyGroup = { link = "Keyword" },
      WhichKeySeparator = { link = "Comment" },
      WhichKeyValue = { link = "Comment" },
    },
  },
}
```

Restart, press Space, and you should get a readable key list instead of a blank popup:

## Live in it for a minute

```python
# inventory/models.py
from dataclasses import dataclass

@dataclass
class Item:
    name: str
    price: float
    quantity: int

def total_value(items: list[Item]) -> float:
    return sum(item.price * item.quantity for item in items)
```

```python
# inventory/report.py
from models import Item, total_value

items = [
    Item("keyboard", 49.99, 3),
    Item("mouse", 19.99, 5),
]

print(f"Inventory value: {total_value(items):.2f}")
```

```sh
cd inventory && git init && git add . && git commit -m "Initial inventory" && nvim
```

Mac: Ctrl stays Ctrl, not Cmd. Forget a key → Space → read which-key.

| Do | Keys |
|---|---|
| Find file | `<Leader>ff` then `rep` → `report.py` |
| Project search | `<Leader>fw` |
| File tree | `<Leader>e` |
| Insert / Normal | `i` / `Esc` |
| Change word under cursor | `ciw` (type, `Esc`, `Ctrl+S`) |
| Undo | `u` |
| Full diagnostic | `gl` |
| Hover / go to def | `K` / `gd` (`Ctrl+O` back) |
| Rename symbol | `<Leader>lr` … then `:wa` (other buffers aren't auto-saved) |
| Claude Code panel (like the VS Code extension) | `<Leader>Ac` open · `<Leader>As` send selection · `<Leader>Aa` accept · `<Leader>Ad` reject |
| Terminal / debug / Git | `F7` · `F9`/`F5`/`F10` · `<Leader>gg` |
| Quit | `:qa` |

Neovim's advantage over clicking: compose. `c`/`d`/`y` + `iw` / `i(` / `i"` / `af`. Line ops `dd`/`p`. Next function `]f`. Repeat `.`

Same as in VS Code, Claude Code often proposes almost-right edits: easy to accept, wrong for what you wanted:

```diff
 def total_value(items: list[Item]) -> float:
-    return sum(item.price * item.quantity for item in items)
+    total = 0.0
+    for item in items:
+        total += item.price * item.quantity * 1.08  # tax??
+    return round(total, 2)
```

Reject the diff or delete the function with `daf` and put the one-liner back. That loop (open, edit, rename, review, run, commit) is ordinary VS Code work, now in Neovim.

## When you want more

`<Leader>fk` searches maps; `<Leader>fh` searches help. Grow `astrocore` from friction, not plugin FOMO:

```lua
-- lua/plugins/astrocore.lua (example)
return {
  "AstroNvim/astrocore",
  opts = {
    options = {
      opt = {
        cmdheight = 1,
        relativenumber = false,
      },
    },

    mappings = {
      n = {
        ["<Leader>W"] = { "<Cmd>wall<CR>", desc = "Save all buffers" },
      },
    },
  },
}
```

Want the wiring without AstroNvim? [kickstart.nvim](https://github.com/nvim-lua/kickstart.nvim). Staying on AstroNvim for years is fine.

## Appendix: installing everything

### What you need

| Tool | Why | Check |
|---|---|---|
| Neovim 0.11+ | Editor (AstroNvim v6 min; written against 0.12) | `nvim --version` |
| Git | Config and plugins | `git --version` |
| Node.js | Most language servers | `node --version` |
| C compiler | Tree-sitter parsers | `gcc --version` or `clang --version` |
| tree-sitter CLI | Parsers | `tree-sitter --version` |
| ripgrep | Project search | `rg --version` |
| fd | File search | `fd --version` |
| Nerd Font | Icons | [Fonts](#fonts-and-icons) |
| lazygit | Git UI | `lazygit --version` |
| Claude Code | Agent | `claude --version` |
| Python 3 | Examples | `python3 --version` |
| Neovide | Optional GUI | `neovide --version` |

Linux clipboard: `wl-clipboard` or `xclip`. nvimforge's flake also pulls ripgrep, fd, tree-sitter, lazygit, Node, and a C compiler.

### Installing the tools

From Neovim's [install guide](https://github.com/neovim/neovim/blob/master/INSTALL.md); Claude Code from [its docs](https://docs.anthropic.com/en/docs/claude-code):

```sh
# macOS
xcode-select --install
brew install neovim git node ripgrep fd lazygit
brew install --cask font-jetbrains-mono-nerd-font

# Windows (PowerShell)
winget install Neovim.Neovim Git.Git OpenJS.NodeJS.LTS \
  BurntSushi.ripgrep.MSVC sharkdp.fd JesseDuffield.lazygit

# Arch
sudo pacman -S neovim git nodejs npm base-devel \
  ripgrep fd tree-sitter-cli lazygit

# Debian / Ubuntu (Neovim from tarball below)
sudo apt install git nodejs npm build-essential ripgrep fd-find unzip

# Other Linux x86_64
curl -LO \
  https://github.com/neovim/neovim/releases/latest/download/nvim-linux-x86_64.tar.gz
sudo tar -C /opt -xzf nvim-linux-x86_64.tar.gz
export PATH="$PATH:/opt/nvim-linux-x86_64/bin"
```

If `nvim --version` is older than 0.11, use the tarball and put the `export` in your shell rc. Debian/Ubuntu: `fd` is `fdfind`. Windows needs a C compiler (e.g. VS Build Tools). Missing tree-sitter CLI: drop the guard in template `lua/plugins/mason.lua`.

### Fonts and icons

[Nerd Font](https://www.nerdfonts.com/font-downloads) in the terminal, or `icons_enabled = false` in `lua/lazy_setup.lua`.

[Install](https://neovide.dev/installation.html), then `neovide` uses this config. GUI font example in `lua/polish.lua`: `vim.o.guifont = "JetBrainsMono Nerd Font:h14"`. Nix: `nix run .#neovide` from nvimforge.

### Windows template path

Same order as above: clone, launch once for the dashboard, quit, then edit in VS Code.

```powershell
Remove-Item $env:LOCALAPPDATA\nvim\.git -Recurse -Force

```

### When it doesn't work

- Boxes for icons → Nerd Font or `icons_enabled = false`
- No highlights → C compiler / tree-sitter CLI on `PATH`
- LSP dead → `:Mason`, language toolchain installed
- No `<Leader>fw` → install ripgrep
- Config ignored → still have `if true then return {} end`
- Stale red errors → `:w` / `:LspRestart`
- No Claude panel → `claude` works in a shell
- Nuclear → `:checkhealth`, or `nvim --clean`

### If you already have a Neovim config

```sh
mv ~/.config/nvim ~/.config/nvim.bak
mv ~/.local/share/nvim ~/.local/share/nvim.bak
mv ~/.local/state/nvim ~/.local/state/nvim.bak
mv ~/.cache/nvim ~/.cache/nvim.bak
```

Windows: `%LOCALAPPDATA%\nvim` and `%LOCALAPPDATA%\nvim-data`.

### Undoing it

```sh
rm -rf ~/.config/nvim \
  ~/.local/share/nvim \
  ~/.local/state/nvim \
  ~/.cache/nvim
mv ~/.config/nvim.bak ~/.config/nvim
mv ~/.local/share/nvim.bak ~/.local/share/nvim
mv ~/.local/state/nvim.bak ~/.local/state/nvim
mv ~/.cache/nvim.bak ~/.cache/nvim
```

### Nix

`nix shell nixpkgs#neovim`; on NixOS add packages to `environment.systemPackages`. Mason + NixOS often needs `programs.nix-ld` or nixpkgs tools instead. nvimforge's `flake.nix` runs this config beside an existing Neovim install.
